# Garmin App Remote

- **BLE spec as YAML (#565).** The wire protocol's single source of truth is `docs/protocol/*.yaml` (dialect in `docs/protocol/README.md`): `constants.yaml`, `characteristics/*.yaml`, `commands.yaml`, `scenarios.yaml`. `docs/garmin-protocol.md` is generated from it - its `<!-- generated: ... -->` regions are rewritten by `python helpers/check_protocol.py build`, and `check` fails if they are out of date. `helpers/check_protocol.py` is the one checker (no code generation): `check` (validate + markdown in sync), `build`, `selftest` (proves broken specs fail), `--repo firmware|client` (drift scan). The native pio test pre-script `test/tools/native_toolchain.py` runs `--repo firmware --repo client` and fails the build on drift, so `pio test` guards it. Spec-first work (spec committed before its code) runs the suites with `PROTOCOL_DRIFT=warn`, which downgrades drift to a warning; never leave it set.
  - **Firmware scan** reads `src/Garmin/GarminProtocol.h`: constants and UUIDs by exact name, enum members as `pascal_case(snake)` (`FIRMWARE_ENUMS` maps the ones that exist; `CommandId` is derived from `commands.yaml`). **Vector scan** (`scan_vectors`) compares every scenario step's hex against a `spec: <scenario>/<step>` tag in `test/**/*.cpp` (the firmware is the reference and carries every board-side step except `board_version/too_old|too_new`, which are the watch's foreign-PROTO reject cases, #567). Tag convention: the `spec:` comment sits on the line above the hex literal(s); a chunked step lists its frames on consecutive lines under one tag; a literal shared by two steps gets stacked `spec:` lines. The 4 genuinely-missing vectors were added to `test/test_garmin_protocol/test_main.cpp` (`sides_swapped/match_start`, `last_known/score_right`, `heart/discard_short`, `results/write`); heart `write_c`/`notify_a`/`notify_b` are also there, not in `test_garmin_link`.
  - **Client scan** (`CLIENT_STEPS`) reads `helpers/garmin_client.py` (PROTO/COMPANY by name, the UUID template, `SCREENS`/`SPORTS`/`ACKS`/`COMMANDS` dicts) and the tags in `helpers/test_garmin_client.py` (which runs standalone: `python helpers/test_garmin_client.py`). The watch and android scans are #567 / #568, not wired yet.
- **Garmin App Remote (#80, in progress on `garmin-app-remote`).** NimBLE-Arduino is pinned at **1.4.3** in `[common]`; `[s3]` sets `CONFIG_BT_NIMBLE_MAX_CONNECTIONS=4` and a 6144 B host task stack (host on core 0, off loop()'s core). Unreferenced, it adds nothing to either image. WiFi/BT software coexistence is on in the core's sdkconfig. **RMT gate passed on V1 (2026-10-02)**: Dev Mode STA + BLE advertising + 2 subscribed centrals (FR970, a phone) at 20 notifies/s + fob presses, in a match: 207,844 refills, 0 bails, 0 stale, max 5 us late; NimBLE took 51.7 KB heap, min free 191 KB. A raw `ble_gattc_notify_custom` from loop() took up to ~1 ms.
- `src/Garmin/` core is pure and header-only (no Arduino/NimBLE/Preferences), host-tested and shipped as is: `GarminProtocol.h` (constants, enums, frame builders, roster CRC-32, state chunking), `WatchCommand.h` (parse: too short -> MALFORMED, trailing bytes ignored per spec 2, `0x0C` unused -> UNKNOWN_CMD), `WatchState.h` (body builder; views use its typed setters, never raw bytes), `Sha256.h` (portable SHA-256/HMAC + constant-time compare; < 0.5 KB stack, it runs in the NimBLE host task), `GarminData.h` (the 174 B `"gar"` blob in namespace `"ns"`, never a `PrefsData` field, and `GarminPairingStore`'s LRU slots; `load()` drops a slot whose `used` is not 0/1 and renumbers the LRU counters). Suites `test_garmin_protocol` / `test_garmin_auth` / `test_garmin_pairing` hold every spec 16.x vector; run them after touching `src/Garmin/`.
- **`GarminService`** (`src/Garmin/GarminService.*`) is the only NimBLE user; the protocol state is the pure, host-tested `GarminLink.h` (`test_garmin_link`), the blob I/O `GarminStore.h`. Off by default; `setup()` calls `begin()` last, only when the stored flag is on, and `loop()` keeps BLE in step with the flag. Init and deinit run in one-shot core-0 tasks, never in `setup()`/`loop()`; a failure is logged and leaves the feature off. An `RTC_NOINIT` marker set across init keeps BLE off **until a power cycle** after any reset inside init (NimBLE `ESP_ERROR_CHECK`s abort), and init is not tried under 80 KB internal heap - a sealed V1 never crash-loops out of OTA reach. Host-task callbacks only call `GarminLink` under one portMUX: byte copies only, never NVS, `printLn`, NimBLE or an HMAC (it runs outside the lock, then the key is re-checked). `loop()` does everything else: per-connection notifies via `ble_gattc_notify_custom` (never `NimBLECharacteristic::notify()` on core 1), terminates, advertising updates, the deferred `"gar"` write. One key per connection; re-issuing a slot drops the connection that proved its old key; only a delivered key restarts the 10 s unauthenticated timeout.
  - `main.cpp` applies **one watch command per 50 ms tick**, after the long-C branch and never in a tick where long C went back, through `DeviceMode::handleWatchCommand` (BACK = `goBack()`, false -> WRONG_SCREEN). Busy screens (`WatchSport::fromModeState().viewDescribes` false: CONFIG, booting) take no command - `ConfigMode::goBack()` saves and leaves; PROFILE takes BACK only. APPLIED plays the fob's sound, except FOCUS and ADD/REMOVE_OFFLINE_GAME (silent; ADD/REMOVE also skip `dismissSplash()`, no screen change - the ack alone pushes the state). Under an Overlay every queued command is answered BUSY. The state is described after `deviceMode->loop()` and published only on change. Test the board from a PC with `helpers/garmin_client.py` (bleak; keys in `~/.scoreboard-garmin/`, never in the repo).
  - **Watch commands reach the same named view methods as the fob** (`togglePlayer`, `startTournament`, `cycleLeft/Right`, `swapSides`, `startMatch`, `setPair`, `score`, `undo`, `skip`, `nextGame`, `selectEntry`, `focusEntry`, `focusOption`, `exitToMenu`); FOCUS (`0x0E`, `target` u32 = sport on MENU, uid or 0 = START on CHOOSE_PLAYERS) is the fob's A/B cursor move through the same method, never acts, and `applyWatchCommand()` acks it APPLIED **without** `gBuzzer.trigger()` (a watch scroll is silent); CHOOSE_PLAYERS' state carries the cursor uid at offset 12, so fob scrolls reach the watch too; the fob handler keeps its own debounce and `preventTriggerForMs`, `handleWatchCommand` only validates arguments (INVALID / WRONG_SCREEN). `DeviceMode::handleWatchCommand` -> `WatchSupport::route`: BUSY while `viewChangePending()` (sport modes: `state != previousState`), then BACK = `goBack()`, then ADD/REMOVE_OFFLINE_GAME (0x0F / 0x10) = `DeviceMode::editOfflineGames()` (default WRONG_SCREEN; sport modes pass `&tournament` only on MATCH_START/INTRO/PLAYING/CELEBRATION/GAME_OVER into `WatchSupport::editOfflineGames`, i.e. `Tournament::addOfflineGame/removeOfflineGame`), else the view - views never see them. PROFILE's BACK is its C/D exit, not `goBack()` (long C there stays a no-op). `describeForWatch` sits beside each view's render code, court side only; `publishWatchState()` skips a pass with a view swap pending. `test_garmin_views` hosts the real views through `view_stubs.h` (pre-defined include guards) - add a stub there for any new display call.
  - **CONFIG has 6 rows** (LED, BUZZER, Dev Mode, GARMIN, RESTART, COFNIJ). GARMIN is a sub-menu entry, not a switch (user's call, 2026-10-03: a switch-looking row that opens a menu holding another switch confused): no tickbox, blue on the LEDs and V1 bar, LED word `GAr` (the 4-letter prefix needs an M); D opens the sub-screen. The on/off is only its AKTYWNY row (`GarminService::isEnabled()`, the `"gar"` blob, never `PrefsData`), LED word `on` / `oFF`. `ConfigMode` has its own deferred state machine (`ConfigModeState`: Menu / Garmin / GarminPairing); long C walks pairing -> GARMIN -> CONFIG -> menu and only the last step saves `PrefsData`. `GarminView`: AKTYWNY (live `setEnabled`), PARUJ (while `!running()` it calls `setEnabled(true)` and waits - blinking `PArU` - then enters pairing on the first pass with `running()`; A/B/C, D elsewhere or `failed()` cancel the wait, no timeout; red only on `failed()`; the mode stays on afterwards), ZAPOMNIJ (first D arms `NA PEWNO?`, a second D forgets, any other key disarms), COFNIJ; footer = paired / connected counts. `GarminPairingView` opens the window in its constructor and closes it in its destructor (every exit), and leaves on its own once a newly paired watch has **authenticated** (`completedPairings()`), never at key delivery - closing wipes the key reply. The e-paper countdown steps by 30 s (a 1 s step would near `MAX_PARTIALS`); the OLED shows exact seconds. Outcome (#523): success closes the window, beeps and plays a green `startRing()`, then leaves CONFIG for the mode selector through `ConfigMode::saveAndLeave()` (the one save+exit, shared with `goBack()`'s Menu branch), so the watch lands on MENU; expiry or a window closed under it plays a red ring, then GARMIN; C/D leave at once, no ring. During the ring fob presses are cleared, long C is refused (`goBack()` false once `outcomeShown()`, through the hand-over tick), the OLED and e-paper keep the code screen, and the hand-over draws no last frame; a `restoreView()` mid-ring skips to the hand-over. `test_garmin_config_view` covers it.
- **Active roster (#85, spec 12).** `setup()` prebuilds both wire tables and CRCs (`setRoster(RosterKind::Players|Teams, ...)`); `buildDeviceMode()` selects the kind first (`useRoster(WatchSport::fromModeState(mode).roster)`, the `roster` column of `WatchSport`'s table is the only sport -> kind mapping). `GarminLink` applies it with the next **published** state (`preparePushes(state)`), never earlier: an ack-only push (overlay) or a host-task STATE read in between would pair the old sport with the new `rosterVersion`, and the watch would cache the roster under the wrong kind. `useRoster` only flips an index under the lock (no copy, no CRC); a version change alone pushes (`pushedRosterVer`). No wire change: an old watch just re-reads on each switch.
- **Protocol v1 + HEART (#501, spec 5 / 18).** `PROTO = 0x01` (v1, frozen at store 1.0.0; v0 was development-only and is refused); every spec 16.x vector starts with `01`, the v0 cases in the suites check that `00` frames are dropped. HEART `0d780008` is the 7th characteristic (3 CCCDs), write + notify, auth only: write `[PROTO, bpm]` (0 clears, trailing bytes ignored), notify `[PROTO, b0, b1, b2]` = the other authenticated connections' non-zero values in slot order, padded with 0. The relay is pure `HeartRelay.h` under GarminLink's lock: `writeHeart` (host task) accepts only while the last **published** screen is PLAYING, `preparePushes` clears every value on any other published screen (an overlay's null push keeps it), a value expires 15 s after its write, a slot is reset on connect / disconnect / lost trust. `takeHeartNotifies` runs in `sendPushes` on the 50 ms tick: at most 1/s per receiver with the newest content, a CCCD enable counts as having been sent the empty list, a failed notify is resent after the window. RAM only, never NVS (privacy policy, `docs/privacy-garmin.md`); never touches STATE, the queue, seq dedupe or the buzzer. Tests `test_heart_*` (link) and `test_heart_frames` (protocol); `garmin_client.py heart <bpm>` drives it from a PC, but a second watch needs another PC or a real watch (Windows shares one link per board).
- **SIDES_SWAPPED (#510, spec 11.3 / 16.11).** `Match::sidesSwapped()` = the pair sits reversed against its first *finished* game (latched in `finishGame()`, so a game left by UNDO at 0:0 does not count; RAM only, lives with the Match = mode lifetime, CHOOSE_PLAYERS and pair cycling keep it). Wire: PLAYING flags bit 6, plus an appended flags byte on INTRO (offset 16), CELEBRATION / GAME_OVER (offset 22) and MATCH_START (offset 20, #513: live with every swap, a hint, never mirrored), filled through `WatchSupport::playing()/result()`, `MatchIntroView` and the three `*MatchStartGameView`s; compatible, no PROTO bump. Bits 4-5 are LAST_KNOWN / LAST_RIGHT (#509), bit 7 reserved.
- **LAST_KNOWN / LAST_RIGHT (#509, spec 11.3 / 16.12).** PLAYING flags bit 4 = the board knows the newest standing point of the game, bit 5 = it is the right side's (only with bit 4); for the watch's BACK-key undo after a reconnect. `GameScoreHistory::newest()` (newest non-`lost` entry) through `WatchSupport::lastPoint()` in the squash / volleyball PLAYING views; padel: the gem's history, else `completedGems.back().winner` (what an UNDO at gem 0:0 steps back into), else unknown. A revived `lost` entry keeps its old place. Compatible, no PROTO bump; tests `test_last_point_state`, `test_*_last_point_flags`.
- **RESULTS (#527 / #563, spec 19 / 16.13-16.14).** `0d780009` is the 8th characteristic, read + write, auth only, **optional for the watch** (a v1 board before it lacks it; the watch's step-2 check stays the seven v1 ones). ROSTER-style cursor: write `[PROTO, index u16]`, a read returns 20 B (header PROTO, index, count u16, `tournamentId` u32, then uidA, uidB, scoreA, scoreB, turn) and advances; past the end the header + `rev` u16 (11 B, which also tells a client the board takes offline games). Source: `Tournament`'s listed games (`listedCount()/listedGame()`, removed offline games skipped; never the raw `getFinishedGame*()`), written only by `Match::finishGame()` (an UNDO at 0:0 never finishes a game) and `Match::recordGame()` (ADD_OFFLINE_GAME); `rev` changes on every non-append change (today a REMOVE); `tournamentId` = `esp_random()` per `Tournament`, never 0 (0 = no tournament). A/B = the match's own pair order, not court sides; turn = `turnOf()` (the pair's k-th listed game, capped at 127), bit 7 = OFFLINE (`TURN_OFFLINE`). `publishWatchState()` calls `GarminService::publishResults(deviceMode->getTournament())` before `publish()`; `GarminLink::syncResults` copies only new games (a new id, a new rev or a shorter list starts over), caps at `RESULTS_MAX` 128, and never pushes. RAM only. `WatchSupport::resultEntry(tournament, listedIndex)` and `editOfflineGames` are templates, so `WatchSupport.h` needs no `Tournament.h`; `GarminService.cpp` includes `LoggerHelper.h` before the Tournament headers (they use `printLn` without including it). Tests `test_results_*` (protocol, link), `test_results_rev_restart`, `test_offline_games` (protocol), `test_offline_games_through_the_modes`, `test_offline_turn_cap`, `test_tournament`, `test_results_through_the_views`; `garmin_client.py results [from]`, `add-game`, `remove-game`.
- **TOURNAMENT (#583, spec 20).** `0d78000a`, the 9th characteristic, read + write, auth only, optional for watches; the tablet drives it. One roster stage (16 x 16 B) and one mirror stage (128 x 15 B) per board, shared by all connections; host-task writes are byte copies, `loop()` takes a stage (copy + clear) when BEGIN/COMMIT answers APPLIED or INVALID, `endTablet()` clears everything. Reads follow a per-connection cursor (STATUS at connect) over a snapshot `publishWatchState` publishes through `publishTablet`/`syncTablet` (zero outside tablet mode). The pushed roster is a third `GarminLink` slot (`setTabletRoster`/`useTabletRoster`); the stored tables are never touched. `TabletSession.h` holds tid, sport and up to 16 profiles at fixed addresses; a re-push keeps every uid at its index and only appends. Commands 0x11-0x14 -> `WatchSupport::route`'s `toTablet` -> `DeviceMode::handleTabletCommand` (default WRONG_SCREEN; logic in `DeviceMode/TabletSupport.h`), silent; TOURNAMENT_WAIT takes BEGIN only. An applied SET_SIDE calls `View::refreshPair()` then `restoreView()`; watch BACK on a tablet MATCH_START is refused (`goBackFromWatch`). Tests `test_tablet_*` (link, protocol), `test_tablet_session`, `test_garmin_views`; `garmin_client.py begin/tstatus/outbox/ack/mirror/set-side`.
